🔎 Aktuelle Probleme

🟥 1. Neue Bestellungen werden nicht in der Liste angezeigt
	•	Du legst Bestellungen erfolgreich an, aber sie erscheinen nicht in der Übersicht.
	•	Mögliche Ursache:
	•	Status ist „draft“, aber der Tabellen-Query filtert auf „sent“ oder „open“.
	•	Die Query (TanStack/React Query oder Backend SQL) enthält evtl.:

WHERE status IN ('sent', 'open')

→ draft-Status wird ignoriert!

⸻

🟥 2. Klick auf eine Bestellung öffnet generischen Modal mit unvollständigen Daten
	•	Die aktuelle Komponente lädt zwar die order, aber zeigt:
	•	Lieferant = Nicht angegeben
	•	Lager = Nicht angegeben
	•	Positionen = Keine angezeigt
	•	Ursachen:
	•	Entweder lädt orderId nicht alle Daten (kein JOIN auf supplier, location, keine Items).
	•	Oder der orderId wird nur die ID übergeben, aber der fetch für Details läuft asynchron und wird beim Öffnen nicht vollständig geladen.

⸻

🟥 3. Kein Einstieg in den echten Bestellprozess möglich (Formular + E-Mail-Versand)
	•	Statt in die ursprüngliche Eingabemaske mit “Produkte auswählen”, “Zusammenfassung”, “Versenden” etc. zu gelangen, öffnet sich nur dieses Mini-Modal.
	•	Die Anwendung erkennt offenbar nicht, dass der Status draft ist und lädt daher nicht die Bearbeitungsmaske.

⸻

🟥 4. Bei „Produkt auswählen“ fehlt ein „Zurück“-Button
	•	Du kannst dich nicht zurück in Schritt 1 (z. B. Lieferant + Lager wählen) bewegen.
	•	Ursache: wahrscheinlich fehlt in der Stepper-Logik der Button für step > 1.

⸻

const orders = await db.order.findMany({
  where: { status: { in: ['draft', 'sent', 'open'] } }

✅ 2. Beim Klick: Routing in den Prozesspfad

if (order.status === 'draft') {

  router.push(`/bestellungen/${order.id}/sent`);
}

Titel: Routing & Bearbeitbarkeit von Bestellungen je nach Status

Beschreibung:

	•	Die Übersichtstabelle muss auch draft-Bestellungen anzeigen.
