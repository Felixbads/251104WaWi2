E-Mail-Benachrichtigungssystem - Vollständige Implementierung

## 🎯 Ziel
Implementiere ein vollständiges, produktionsreifes E-Mail-Benachrichtigungssystem mit täglichen Reports, Trigger-basierten Alerts und flexibler Template-Verwaltung.

## 📋 Systemkomponenten

### 1. **Kern-Service Architecture**

#### A) Daily Email System
- **`dailyEmailService.ts`** - Hauptsteuerung für tägliche E-Mails
- **`dailyEmailDataAggregator.ts`** - Datensammlung und -aufbereitung
- **`dailyEmailComposer.ts`** - HTML/Text-Template-Rendering
- **`dailyEmailScheduler.ts`** - Zeitgesteuerte Ausführung

#### B) Notification System
- **`notificationService.ts`** - Zentrale Benachrichtigungslogik
- **`emailService.ts`** - SMTP-Versand und -Konfiguration
- **Trigger Services** in `/server/services/triggers/`:
  - `cashHighTrigger.ts` - Hoher Geldbestand
  - `coinLowTrigger.ts` - Wenig Münzgeld
  - `stockLowTrigger.ts` - Niedriger Lagerbestand
  - `mhdSoonTrigger.ts` - Nahende MHD-Ablaufdaten
  - `salesYesterdayTrigger.ts` - Gestrige Verkaufszahlen
  - `salesWeeklyTrigger.ts` - Wöchentliche Verkaufsberichte
  - `forecastWeekTrigger.ts` - Wochenprognosen
  - `marginReportTrigger.ts` - Margen-Berichte

#### C) Template Management
- **Handlebars Templates** in `/server/templates/notifications/`:
  - `cash_high.hbs`
  - `coin_low.hbs`
  - `stock_low.hbs`
  - `mhd_soon.hbs`
  - `sales_yesterday.hbs`
  - `sales_weekly.hbs`
  - `forecast_week.hbs`
  - `margin_report.hbs`

### 4. **Datenstrukturen**

#### Database Schema
```sql
-- Email-Konfiguration
CREATE TABLE email_settings (
  id SERIAL PRIMARY KEY,
  smtp_host VARCHAR(255),
  smtp_port INTEGER,
  smtp_user VARCHAR(255),
  smtp_pass VARCHAR(255),
  smtp_secure BOOLEAN DEFAULT true,
  from_name VARCHAR(255),
  from_email VARCHAR(255),
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- Daily Email Einstellungen
CREATE TABLE daily_email_settings (
  id SERIAL PRIMARY KEY,
  enabled BOOLEAN DEFAULT false,
  send_time TIME DEFAULT '08:00:00',
  timezone VARCHAR(50) DEFAULT 'Europe/Berlin',
  include_sales BOOLEAN DEFAULT true,
  include_inventory BOOLEAN DEFAULT true,
  include_alerts BOOLEAN DEFAULT true,
  include_forecasts BOOLEAN DEFAULT false,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- E-Mail-Empfänger
CREATE TABLE email_recipients (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  name VARCHAR(255),
  role VARCHAR(100),
  active BOOLEAN DEFAULT true,
  daily_reports BOOLEAN DEFAULT true,
  alerts BOOLEAN DEFAULT true,
  forecasts BOOLEAN DEFAULT false,
  created_at TIMESTAMP DEFAULT NOW()
);

-- Benachrichtigungs-Zeitpläne
CREATE TABLE notification_schedules (
  id SERIAL PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  trigger_type VARCHAR(100) NOT NULL,
  enabled BOOLEAN DEFAULT true,
  schedule_config JSONB,
  conditions JSONB,
  template_type VARCHAR(100),
  last_run TIMESTAMP,
  next_run TIMESTAMP,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- Abonnements
CREATE TABLE notification_subscriptions (
  id SERIAL PRIMARY KEY,
  recipient_id INTEGER REFERENCES email_recipients(id),
  schedule_id INTEGER REFERENCES notification_schedules(id),
  active BOOLEAN DEFAULT true,
  created_at TIMESTAMP DEFAULT NOW()
);

-- E-Mail-Logs
CREATE TABLE email_logs (
  id SERIAL PRIMARY KEY,
  recipient_email VARCHAR(255),
  subject VARCHAR(500),
  type VARCHAR(100),
  status VARCHAR(50),
  error_message TEXT,
  sent_at TIMESTAMP DEFAULT NOW(),
  template_used VARCHAR(100),
  data_snapshot JSONB
);

-- Template-Speicherung
CREATE TABLE email_templates (
  id SERIAL PRIMARY KEY,
  type VARCHAR(100) UNIQUE NOT NULL,
  name VARCHAR(255),
  subject_template TEXT,
  html_template TEXT,
  text_template TEXT,
  variables JSONB,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

interface EmailSettings {
  id?: number;
  smtp_host: string;
  smtp_port: number;

  smtp_pass: string;
  smtp_secure: boolean;
  from_name: string;
  from_email: string;
}

// Daily Email Einstellungen
interface DailyEmailSettings {
  id?: number;
  enabled: boolean;
  send_time: string;
  timezone: string;
  include_sales: boolean;
  include_inventory: boolean;
  include_alerts: boolean;
  include_forecasts: boolean;
}

// Empfänger
interface EmailRecipient {
  id?: number;
  email: string;
  name?: string;
  role?: string;
  active: boolean;
  daily_reports: boolean;
  alerts: boolean;
  forecasts: boolean;
}

// Benachrichtigungs-Zeitplan
interface NotificationSchedule {
  id?: number;
  name: string;
  trigger_type: string;
  enabled: boolean;
  schedule_config: {
    frequency: 'daily' | 'weekly' | 'monthly' | 'on_condition';
    time?: string;
    days_of_week?: number[];
    day_of_month?: number;
    conditions?: any;
  };
  conditions: any;
  template_type: string;
  last_run?: Date;
  next_run?: Date;
}

// Daily Report Daten-Struktur
interface DailyReportData {
  template: string;
  date: string;

  sections: {
    verkäufe: SalesData;
    bestände_logistik: InventoryData;

    automaten_status: MachineStatusData;
    wetter_ferien_umsatz?: WeatherData;
    offene_wareneingänge?: OpenOrdersData;
    agent_analyse?: AgentAnalysisData;
  };
  hinweise: string[];
}

### 5. **Implementierungsschritte**

#### Phase 1: Basis-Infrastructure
1. **Database Setup**
   - Erstelle alle notwendigen Tabellen
   - Implementiere Migrationen
   - Setze Grundkonfiguration

2. **Core Services**
   - `emailService.ts` - SMTP-Basis-Funktionalität
   - `notificationService.ts` - Zentrale Benachrichtigungslogik
   - Template-System mit Handlebars

#### Phase 2: Daily Email System
1. **Data Aggregation**
   - `dailyEmailDataAggregator.ts` - Vollständige Datensammlung
   - Verkaufsdaten, Lagerbestände, Alerts, Wetterprognosen
   - MHD-FIFO Integration

2. **Template Rendering**
   - `dailyEmailComposer.ts` - HTML/Text-Generierung
   - Responsive E-Mail-Templates
   - Bedingte Sektionen

3. **Scheduling**
   - `dailyEmailScheduler.ts` - Zeitgesteuerte Ausführung
   - Cron-Job Integration
   - Fehlerbehandlung

#### Phase 3: Trigger-basierte Benachrichtigungen
1. **Trigger Services implementieren**
   - Hoher Geldbestand (`cashHighTrigger.ts`)
   - Niedriger Münzbestand (`coinLowTrigger.ts`)
   - Niedrige Lagerbestände (`stockLowTrigger.ts`)
   - Nahende MHD-Ablaufdaten (`mhdSoonTrigger.ts`)
   - Verkaufsberichte (`salesYesterdayTrigger.ts`, `salesWeeklyTrigger.ts`)
   - Prognose-Alerts (`forecastWeekTrigger.ts`)
   - Margen-Berichte (`marginReportTrigger.ts`)

2. **Condition Engine**
   - Flexible Bedingungsprüfung
   - Schwellenwerte und Regeln
   - Zeitfenster-Logik

#### Phase 4: Frontend Management
1. **Admin-Interfaces**
   - E-Mail-Konfiguration
   - Empfänger-Verwaltung
   - Template-Editor
   - Zeitplan-Management

2. **Monitoring & Logs**
   - Versand-Protokolle
   - Error-Tracking
   - System-Status

#### Phase 5: Testing & Deployment
1. **Test-Framework**
   - Unit-Tests für alle Services
   - Integration-Tests
   - E-Mail-Preview-System

2. **Production Features**
   - Rate Limiting
   - Retry-Mechanismen
   - Monitoring-Integration

### 7. **Template-Beispiele**

```handlebars
<!-- server/templates/notifications/daily_report.hbs -->
<!DOCTYPE html>
<html>
<head>
    <meta charset="UTF-8">
    <title>{{betreff}}</title>
    <style>
        /* Responsive E-Mail-Styles */
    </style>
</head>
<body>
    <h1>📊 Tagesreport – {{date}}</h1>
    
    {{#if sections.verkäufe}}
    <section>
        <h2>💰 Verkäufe</h2>
        <p>Gesamtumsatz: €{{sections.verkäufe.gesamtumsatz}}</p>
        <p>Anzahl Verkäufe: {{sections.verkäufe.anzahl_verkäufe}}</p>
    </section>
    {{/if}}
    
    {{#if sections.bestände_logistik}}
    <section>
        <h2>📦 Bestände & Logistik</h2>
        {{#if sections.bestände_logistik.niedriger_lagerbestand}}
        <h3>⚠️ Niedrige Lagerbestände</h3>
        <ul>
        {{#each sections.bestände_logistik.niedriger_lagerbestand}}
            <li>{{produkt}}: {{bestand}} (Mindest: {{schwellenwert}})</li>
        {{/each}}
        </ul>
        {{/if}}
    </section>
    {{/if}}
    
    <!-- Weitere Sektionen... -->
</body>
</html>
```
