Warum Dein ursprüngliches Problem immer noch auftritt

1. Bestellung erscheint nicht in der Übersicht

// v4
queryClient.invalidateQueries({ queryKey: ['/api/orders'] });

	•	Create-POST: /orders
	•	fetch in OrdersOverview (höchst­wahrscheinlich): useQuery(['orders'], …) oder ['/orders']
	•	Invalidation: ['/api/orders']

→ Drei unterschiedliche Keys/URLs ⇒ React-Query hält den Cache der Übersicht weiter für gültig.
Fix: Verwende exakt denselben Key wie im Overview-Component, z. B.

queryClient.invalidateQueries({ queryKey: ['orders'] });

oder

queryClient.invalidateQueries({ queryKey: ['/orders'] });

Prüfe im Overview-Code nach, welcher Key dort wirklich benutzt wird!

⸻

2. Kein echter „Versand/Wareneingang“-Schritt
	•	Du setzt weiter setStep('goodsReceipt').
	•	In getStepContent('goodsReceipt') zeigst Du sofort die Erfolgskarte („Bestellung … gesendet“).
	•	Ein gesonderter Workflow für Versand vorbereiten / Wareneingänge erfassen existiert also nicht – deshalb „kommst Du nicht auf die Versandseite“.

Lösungs-Optionen
	1.	Neuen Step einführen (z. B. 'shipping' oder 'warehouseReceipt')

case 'summary':        return 'shipping';
case 'shipping':       return 'goodsReceipt';


	2.	Oder wenn goodsReceipt die Versandseite sein soll:
setze erst goodsReceipt wenn der Nutzer im Dialog wirklich „Senden“ klickt – nicht vorher.

⸻

3. Dialog öffnet sich, aber Email-Versand scheitert → Step bleibt stehen

generatePDFAndSendEmail() ruft gleich danach:

const response = await fetch(`/api/orders/${orderIdToUse}`);

Wenn Deine REST-Route eigentlich /orders/:id heißt, bekommt der Fetch ein 404 → der Code bricht im catch ab, der Dialog öffnet sich nicht. Du landest trotzdem in goodsReceipt, siehst aber eine Karte, die vorgibt, es sei alles schon verschickt.

Fix
	•	Nimm die Order-Daten aus der Antwort von createOrderMutation (data) – Du hast sie ja bereits.
	•	Vermeide den Extra-Fetch oder korrigiere den Pfad:

const response = await fetch(`/orders/${orderIdToUse}`);



⸻

4. Übersicht, E-Mail und Versand zusammenspielen lassen
	1.	Nach CREATE
	•	setOrderId(data.id);
	•	kein setStep hier – warte erst auf den Dialog-Flow.
	2.	Nach erfolgreichem Versand (in OrderEmailDialog → „Senden“)
	•	markOrderAsSentMutation.mutate({...})
	•	setStep('goodsReceipt');
	•	queryClient.invalidateQueries({ queryKey: ['orders'] });
