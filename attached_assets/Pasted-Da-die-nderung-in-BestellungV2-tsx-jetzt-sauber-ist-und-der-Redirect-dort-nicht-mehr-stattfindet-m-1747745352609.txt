Da die Änderung in BestellungV2.tsx jetzt sauber ist und der Redirect dort nicht mehr stattfindet, müssen wir auf der nächsten Ebene in OrderEmailPage ansetzen, denn genau dort ruft man nach dem Senden immer noch implizit den onNext-Callback. So gehen wir jetzt systematisch vor:

⸻

1. OrderEmailPage instrumentieren
	1.	Debug-Log beim Mounten
Füge ganz oben in OrderEmailPage.tsx (direkt in der Komponente) ein:

useEffect(() => {
  console.log('[OrderEmailPage] mounted, props:', { onNext, autoSend: props.autoSend });
  return () => console.log('[OrderEmailPage] unmount');
}, []);


	2.	Debug-Log vor onNext()
In dem Block, wo nach erfolgreichem Versand onNext() aufgerufen wird, ersetze

if (onNext) {
  onNext();
}

durch

if (onNext) {
  console.log('[OrderEmailPage] calling onNext() now');
  onNext();
} else {
  console.log('[OrderEmailPage] no onNext callback passed');
}


	3.	Guard einbauen, dass erst ein Button-Klick den Callback feuert
Statt das onNext() direkt nach dem await sendEmail() zu rufen, verlege den Aufruf in einen echten „Schließen“-Button:

{emailSent && (
  <Button onClick={() => {
    console.log('[OrderEmailPage] user closed the dialog');
    onNext?.();
  }}>
    Zur Übersicht
  </Button>
)}

Entferne überall sonst das automatische onNext().
