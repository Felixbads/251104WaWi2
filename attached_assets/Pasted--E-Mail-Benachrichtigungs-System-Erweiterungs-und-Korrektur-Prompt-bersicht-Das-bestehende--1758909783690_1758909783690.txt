
# E-Mail-Benachrichtigungs-System: Erweiterungs- und Korrektur-Prompt

## Übersicht
Das bestehende E-Mail-Benachrichtigungssystem muss um kritische Überwachungsfunktionen erweitert und bestehende Probleme behoben werden.

## 🎯 Prioritäre Erweiterungen

### 1. MHD-Warnungen für Automaten
**Anforderung:** Automatische Überwachung und Benachrichtigung bei ablaufenden Produkten in Automaten

**Implementierung:**
- Neue Trigger-Klasse: `MhdSoonTrigger` (erweitern von bestehender)
- Überwachung der `machine_stocks` Tabelle auf `expiry_date`
- Warnstufen:
  - 🔴 KRITISCH: ≤1 Tag bis Ablauf (sofortige Benachrichtigung)
  - 🟡 WARNUNG: ≤3 Tage bis Ablauf (tägliche Benachrichtigung)
  - 🟢 BEOBACHTEN: ≤7 Tage bis Ablauf (wöchentliche Benachrichtigung)

**Template-Anpassungen:**
- Erweitere `mhd_soon.hbs` um Automaten-spezifische Daten
- Füge Standort-Informationen und Servicetechniker-Kontakte hinzu
- Zeige Warenwert der betroffenen Produkte an

### 2. Hoher Geldbestand in Automaten
**Anforderung:** Überwachung der Bargeld-Bestände und automatische Leerungsempfehlungen

**Implementierung:**
- Erweitere `CashHighTrigger` um verbesserte Schwellenwerte
- Überwachung von `machines.cashCredit` und `machines.cardCredit`
- Schwellenwerte:
  - 🟡 WARNUNG: >500€ (Leerung in 24h empfohlen)
  - 🔴 KRITISCH: >1000€ (Sofortige Leerung erforderlich)
  - 🚨 SICHERHEITSRISIKO: >1500€ (Notfall-Protokoll)

**Template-Features:**
- Bargeld-Verlauf der letzten 7 Tage
- Empfohlener Leerungstermin basierend auf Umsatztrend
- Sicherheitsprotokoll-Hinweise

### 3. Lange keine Kartenzahlung
**Anforderung:** Überwachung der Kartenzahlungs-Funktionalität

**Implementierung:**
- Neue Trigger-Klasse: `CardPaymentInactiveTrigger`
- Überwachung der `transactions` Tabelle nach `paymentMethod = 'CASHLESS'`
- Warnstufen:
  - 🟡 WARNUNG: >24h keine Kartenzahlung
  - 🔴 KRITISCH: >48h keine Kartenzahlung
  - 🚨 AUSFALL: >72h keine Kartenzahlung

**Überwachungslogik:**
```sql
SELECT machine_id, machine_name, 
       MAX(datetime) as last_card_payment,
       EXTRACT(HOURS FROM (NOW() - MAX(datetime))) as hours_since_last
FROM transactions t
JOIN machines m ON t.machine_id = m.id
WHERE payment_method = 'CASHLESS'
GROUP BY machine_id, machine_name
HAVING EXTRACT(HOURS FROM (NOW() - MAX(datetime))) > 24
```

### 4. Lange kein Alkoholverkauf
**Anforderung:** Überwachung der Alkohol-Verkäufe zur Compliance-Sicherstellung

**Implementierung:**
- Neue Trigger-Klasse: `AlcoholSalesInactiveTrigger`
- Überwachung basierend auf Produkt-Kategorien oder Alkohol-Flag
- Warnstufen:
  - 🟡 HINWEIS: >7 Tage kein Alkoholverkauf
  - 🔴 AUFFÄLLIG: >14 Tage kein Alkoholverkauf
  - 🚨 PRÜFUNG: >30 Tage kein Alkoholverkauf

**Überwachungslogik:**
```sql
SELECT machine_id, machine_name,
       MAX(t.datetime) as last_alcohol_sale,
       EXTRACT(DAYS FROM (NOW() - MAX(t.datetime))) as days_since_last
FROM transactions t
JOIN machines m ON t.machine_id = m.id
JOIN products p ON t.product_id = p.id
WHERE p.category_id IN (SELECT id FROM categories WHERE name ILIKE '%alkohol%')
   OR p.product_name ILIKE '%bier%' 
   OR p.product_name ILIKE '%wein%'
   OR p.is_alcoholic = true
GROUP BY machine_id, machine_name
HAVING EXTRACT(DAYS FROM (NOW() - MAX(t.datetime))) > 7
```

## 🔧 Kritische Fehlerbehebungen

### 5. Umsatz-Null-Problem beheben
**Problem:** Umsatz wird als Null angezeigt in E-Mail-Berichten

**Diagnose-Schritte:**
1. **Datenbank-Abfrage prüfen:** Überprüfe `DailyEmailDataAggregator.getSalesAnalysis()`
2. **Zeitraum-Filter:** Stelle sicher, dass der korrekte Datumsbereich verwendet wird
3. **Währungs-Formatierung:** Prüfe Decimal-zu-Number Konvertierung
4. **Template-Rendering:** Überprüfe Platzhalter-Ersetzung in `DailyEmailComposer`

**Korrekturen:**
```typescript
// In DailyEmailDataAggregator.ts
private async getSalesAnalysis(reportDate: Date) {
    const dayStart = new Date(reportDate);
    dayStart.setHours(0, 0, 0, 0);
    const dayEnd = new Date(reportDate);
    dayEnd.setHours(23, 59, 59, 999);

    const salesData = await db
        .select({
            totalRevenue: sql<number>`COALESCE(SUM(CAST(${transactions.price} AS DECIMAL)), 0)`.as('totalRevenue'),
            transactionCount: count(transactions.id).as('transactionCount')
        })
        .from(transactions)
        .where(
            and(
                gte(transactions.datetime, dayStart),
                lte(transactions.datetime, dayEnd),
                // Stelle sicher, dass price nicht null ist
                sql`${transactions.price} IS NOT NULL AND ${transactions.price} > 0`
            )
        );

    return {
        anzahl_verkäufe: Number(salesData[0]?.transactionCount) || 0,
        umsatzsumme: Number(salesData[0]?.totalRevenue) || 0,
        // ... weitere Felder
    };
}
```
