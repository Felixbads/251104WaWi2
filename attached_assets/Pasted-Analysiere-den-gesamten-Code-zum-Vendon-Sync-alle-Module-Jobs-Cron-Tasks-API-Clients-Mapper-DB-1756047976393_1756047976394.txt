## 4. DATENBANKPRÜFUNG

### Relevante Tabellen:

```sql
-- Transaktionen
CREATE TABLE transactions (
  id SERIAL PRIMARY KEY,
  vendon_id VARCHAR(255) UNIQUE NOT NULL,
  machine_id INTEGER REFERENCES machines(id),
  product_id VARCHAR(255),
  product_name TEXT,
  quantity INTEGER NOT NULL DEFAULT 1,
  amount INTEGER, -- in Cent
  price REAL,
  price_vat REAL,
  price_wo_vat REAL,
  payment_method VARCHAR(50),
  datetime TIMESTAMPTZ NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Maschinen
CREATE TABLE machines (
  id SERIAL PRIMARY KEY,
  vendon_id INTEGER UNIQUE NOT NULL,
  machine_name TEXT NOT NULL,
  location_id INTEGER,
  last_sync TIMESTAMPTZ
);

-- Produkte  
CREATE TABLE products (
  id SERIAL PRIMARY KEY,
  vendon_id INTEGER UNIQUE,
  product_name TEXT NOT NULL,
  cost_price REAL,
  deposit_price REAL,
  is_active BOOLEAN DEFAULT true
);
```

## 8. ERGEBNISFORMAT

### A. TL;DR:
Vendon-Sync funktioniert für aktuelle Daten (✅), historisches Backfill problematisch (⚠️), Geo-Daten gehen verloren (❌). Rate-Limiting stabil, Duplicate-Prevention funktioniert. Hauptproblem: Machine-Lookups bei Refills schlagen fehl.

### B. Systemkarte:
Scheduler → vendonAPI → enhancedMapping → DB-Upsert → sync_logs

### C. Coverage-Matrix:
72/85 API-Felder gemappt (85%), 8 Felder fehlen, 5 Transformations-Probleme

### D. Fundstellen:
❌ server/services/vendonSync.ts:245 - Machine-Lookup für Refills
❌ server/services/enhancedVendonMapping.ts:89 - Geo-Location nicht persistiert  
⚠️ server/services/historicalVendonSync.ts:156 - Timeout bei großen Batches

### E. Fix-/Migrationsplan:
```sql
-- 1. Geo-Location Spalten hinzufügen
ALTER TABLE transactions ADD COLUMN location_lat REAL;
ALTER TABLE transactions ADD COLUMN location_lng REAL;

-- 2. Machine-Lookup Index optimieren  
CREATE INDEX CONCURRENTLY idx_machines_vendon_id ON machines(vendon_id);

-- 3. Batch-Size reduzieren
UPDATE sync_settings SET batch_size = 500 WHERE service = 'historical_sync';
```

### F. Risiken/Rollout:
- Backfill für Geo-Daten: ~50k Records (2h Downtime)
- Machine-Index: Online-Migration möglich
- Monitoring: 48h Überwachung nach Deployment
