Wiederkehrende Bestellungen - Konzept und Implementierung
Das System verfügt über ein vollständig implementiertes System für wiederkehrende Bestellungen mit folgenden Kernkomponenten:

1. Datenbankstruktur (schema.ts)
Das System basiert auf drei Haupttabellen:

recurringOrders - Konfiguration der wiederkehrenden Bestellungen
recurringOrderItems - Produktpositionen für jede wiederkehrende Bestellung
recurringOrderExecutions - Protokoll aller Ausführungen
2. Bestelltypen und Intervalle
Bestelltypen:

shipping - Versandbestellungen an Lieferanten
goods_receipt - Wareneingänge für Lager
Intervalle:

weekly - Wöchentlich
biweekly - Alle 2 Wochen
triweekly - Alle 3 Wochen
monthly - Monatlich
3. Intelligente Prognose-Integration
Das System unterstützt zwei Modi:

Shopping Cart Modus (Standard):

Prognose wird nur auf ausgewählte Produkte angewendet
Mengen werden basierend auf historischen Verkaufsdaten angepasst
Konfidenz-Level bestimmt, ob Prognose verwendet wird (>60%)
All-Produkte Modus (Legacy):

Automatische Prognose für alle Lieferanten-Produkte
Erstellt Bestellpositionen basierend auf Verkaufsprognosen
4. Automatischer Scheduler (recurringOrderScheduler.ts)
Zeitsteuerung:

5. Bestellerstellung-Workflow
Auslösung: Scheduler prüft fällige Bestellungen
Prognose: Mengenanpassung basierend auf historischen Daten
Bestellerstellung: Automatische Erstellung als reguläre Bestellung
Status-Unterscheidung:
Versandbestellungen → Status: draft
Wareneingänge → Status: goods_receipt
6. E-Mail-Benachrichtigungen
Automatische Benachrichtigungen mit:

Bestelldetails und Produktliste
Unterschiedliche Templates je nach Bestelltyp
HTML-formatierte E-Mails mit Tabellen
Nächste Schritte je nach Workflow

Funktionen:
