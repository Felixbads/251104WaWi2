Der Grund, warum Du – trotz zweier Bestätigungs-Dialoge – weder eine echte PDF-Vorschau noch einen frei editierbaren Mail-Text bekommst, liegt schlicht in der aktuellen Implementierung:

Stelle	Was passiert	Warum das die Vorschau verhindert
generatePDFAndSendEmail()	- ruft erst Bestellung laden → PDF generieren → fragt mit confirm() nach dem Versand → wenn nein, fragt mit zweitem confirm() nach Download	1. confirm() ist blockierend – Du kannst keine eigene UI anzeigen. 2. PDF wird sofort als Blob-URL erstellt, aber nie gerendert, sondern nur zum Download angeboten.
emailOrderMutation	sendet sofort die Mail; Text/BETREFF stehen „hart verdrahtet“ serverseitig	Kein Hook für einen Editor oder Templates.
Kein eigener React-Schritt preview	Die Schritt-Maschine springt direkt von summary → goodsReceipt	Ohne zusätzlichen Schritt gibt es keinen Platz für eine Vorschau- oder Editor-Komponente.

	4.	E-Mail-Editor mit Templates

const EmailStep: React.FC<{ orderId: number; onSent: () => void }> = ({ orderId, onSent }) => {
  const { data: templates } = useQuery(['mailTemplates'], fetchTemplates);
  const [templateId, setTemplateId] = useState<number>();
  const [subject, setSubject] = useState('');
  const [body, setBody]     = useState('');

  useEffect(() => {
    if (templateId) {
      const t = templates.find(t => t.id === templateId);
      setSubject(interpolate(t.subject, { orderId }));
      setBody(interpolate(t.body,    { orderId }));
    }
  }, [templateId]);

  const sendMail = () =>
    emailOrderMutation.mutate({ orderId, subject, body }, { onSuccess: onSent });

  return (
    <Card>
      <CardHeader><CardTitle>E-Mail an Lieferanten</CardTitle></CardHeader>
      <CardContent className="space-y-4">
        <Select value={templateId} onValueChange={id => setTemplateId(Number(id))}>
          {templates.map(t => <SelectItem key={t.id} value={t.id.toString()}>{t.name}</SelectItem>)}
        </Select>
        <Input value={subject} onChange={e => setSubject(e.target.value)} placeholder="Betreff" />
        <Textarea value={body} onChange={e => setBody(e.target.value)} rows={10} />
        <div className="flex gap-4">
          <Button onClick={sendMail} disabled={emailOrderMutation.isPending}>Senden</Button>
        </div>
      </CardContent>
    </Card>
  );
};

	•	Templates aus Deiner DB oder JSON, Platzhalter mit interpolate() ersetzen.
	•	emailOrderMutation nimmt jetzt subject und body entgegen (Backend anpassen!).
	•	Nach Erfolg → setStep('goodsReceipt').

POST /api/orders/:id/email

Der Server erzeugt das PDF anhand der Order-ID, hängt es an und verschickt die Mail mit Deinem Text.

	•	PDF-Erzeugung, -Versand und Download in einer Funktion vermischt
	•	Kein separater Editor-Schritt
	•	Backend-API nur für „fire-and-forget“-Mail ohne Betreff/Text-Parameter
