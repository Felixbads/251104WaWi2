
# WAREHOUSE3 SYSTEM: KRITISCHE FEHLERBEHEBUNG UND FIFO-AUTOMATISIERUNG

## SYSTEMKONTEXT
Du arbeitest am Warehouse3-Lagerverwaltungssystem eines Automatenbetreibers. Das System verwaltet Lagerbestände, Produktchargen mit MHD, Warenbewegungen und Automaten-Refills mit FIFO-Logik.

## AKTUELLE ARCHITEKTUR
- **Backend**: Node.js/Express mit Drizzle ORM, PostgreSQL
- **Frontend**: React/TypeScript mit TanStack Query
- **Haupttabellen**: 
  - `warehouses` - Lagerdefinitionen
  - `inventory_items` - Aktuelle Bestände pro Produkt/Lager
  - `product_batches` - Chargen mit MHD für FIFO
  - `inventory_movements` - Audit-Trail aller Bewegungen
  - `machine_warehouse_assignments` - Automaten-Zuordnungen

## KRITISCHE PROBLEME ZU BEHEBEN

### 1. FIFO-LOGIK UNVOLLSTÄNDIG
**Problem**: Batch-Auswahl erfolgt nicht immer nach FIFO (First In, First Out)
**Dateien**: 
- `server/services/mhdFifoService.ts` - Hauptlogik
- `server/routes/warehouse3.routes.ts` - API-Endpunkte
- `server/services/inventoryTransactions.ts` - Transaktionsabwicklung

**Symptome**:
- MHD-basierte Sortierung fehlt bei Entnahmen
- Automatische FIFO-Selektion nicht implementiert
- Chargen werden nicht nach Ablaufdatum priorisiert

**Anforderungen**:
```sql
-- FIFO-Sortierung muss immer erfolgen nach:
ORDER BY expiry_date ASC, received_date ASC
```

### 2. PERFORMANCE-PROBLEME
**Problem**: Komplexe Bewegungs-Queries führen zu Timeouts (>2s)
**Betroffene Endpunkte**:
- `/api/warehouse3/warehouses/:id/stats` (slow: 2046ms)
- `/api/warehouse3/warehouses/:id/movements`

**Symptome**:
```
[2025-09-25 13:03:14.442 +0000] WARN: [] Slow request detected: 2046ms
```

**Zu optimieren**:
- Bewegungsprotokoll-Abfragen mit komplexen Joins
- Warehouse-Statistik-Berechnungen
- Batch-Verfügbarkeits-Checks

### 3. REFILL-INTEGRATION PROBLEME
**Problem**: Vendon-Refills werden nicht automatisch verarbeitet
**Dateien**:
- `server/services/refillProcessingService.ts`
- `server/services/legacyRefillProcessingService.ts`
- `server/routes/warehouse3.routes.ts` - MHD-Transfer-Endpoint

**Symptome**:
- Manuelle Refill-Prozesse parallel zu automatischen
- MHD-Daten werden nicht korrekt übertragen
- Bestandsreduzierung im Lager fehlt

### 4. WARENEINGANG-DISCONNECT
**Problem**: Goods-Receipt läuft über separates System
**Dateien**:
- `server/routes/goods-receipt.ts` - Separates System
- `server/services/goodsReceiptService.ts`
- `server/services/inventoryTransactions.ts` - Sollte integriert werden

**Symptome**:
- Nicht direkt in Warehouse3 Dashboard sichtbar
- Doppelte Datenerfassung
- Inkonsistente Bestandsführung

### 5. FEHLENDE KERNFUNKTIONEN
**Probleme**:
- Umlagerungen zwischen Lagern nicht implementiert
- Direkte Entnahme-Funktionen fehlen
- Bestandswarnung-System nicht aktiv
- Automatische Benachrichtigungen bei niedrigen Beständen fehlen

### DATENBANK-INKONSISTENZEN
```sql
-- 1. Verwaiste Batch-Records
SELECT COUNT(*) FROM product_batches pb 
LEFT JOIN inventory_items ii ON pb.product_id = ii.product_id 
AND pb.warehouse_id = ii.warehouse_id 
WHERE ii.id IS NULL;

-- 2. Fehlende Bewegungsprotokoll-Einträge  
SELECT COUNT(*) FROM inventory_items 
WHERE last_updated > '2025-01-01' 
AND id NOT IN (
  SELECT DISTINCT inventory_item_id 
  FROM inventory_movements 
  WHERE performed_at > '2025-01-01'
);

-- 3. FIFO-Inkonsistenz: Neuere Chargen vor älteren verbraucht
SELECT * FROM product_batches 
WHERE status = 'consumed' 
AND expiry_date > (
  SELECT MIN(expiry_date) FROM product_batches pb2 
  WHERE pb2.product_id = product_batches.product_id 
  AND pb2.warehouse_id = product_batches.warehouse_id 
  AND pb2.status = 'active'
);
```
