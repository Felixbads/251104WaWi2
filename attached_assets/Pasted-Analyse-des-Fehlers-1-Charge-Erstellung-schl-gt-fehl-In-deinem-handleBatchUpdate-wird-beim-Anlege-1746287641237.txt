Analyse des Fehlers
	1.	Charge-­Erstellung schlägt fehl
In deinem handleBatchUpdate wird beim Anlegen einer neuen Charge folgender Fetch-Aufruf gemacht:

const createRes = await fetch('/api/inventory-counts/product-batches', { … });
if (!createRes.ok) {
  throw new Error(`Batch konnte nicht angelegt werden: ${createRes.status}`);
}

Da der Server hier mit einem Fehlercode (404 oder 400 o. Ä.) antwortet, endet jeder neue Batch-Versuch im Catch-Block, und du bekommst die Meldung
„Die Charge konnte nicht erstellt oder verknüpft werden.“

Warum? Vermutlich erwartet dein Backend den Endpunkt oder die Nutzdaten anders:
	•	Falscher URL-Pfad: Möglicherweise muss die Inventur-ID (id) in der URL stehen, z. B.

`/api/inventory-counts/${id}/product-batches`

statt /api/inventory-counts/product-batches.

	•	Fehlendes Feld im Payload: Der Server braucht vielleicht ein inventoryCountId oder countId im JSON-Body, wird aber nicht mitgesendet.

	2.	Ständiges Neuladen und Scroll-Reset
Jeder erfolgreiche oder fehlgeschlagene Mutations-Aufruf invalidiert aktuell eure Query komplett, wodurch React Query:
	•	die Daten neu lädt und die Komponente komplett re-rendert,
	•	und dabei der Browser-Scroll immer wieder zum Anfang springt.

⸻

🚀 Lösungsvorschlag
	1.	Endpunkt und Payload korrigieren
Ändere den Fetch zur Charge-Erstellung so, dass er genau dem API-Contract entspricht. Beispiel, falls eure API den Inventur-Kontext braucht:

// URL inkl. inventurId
const url = `/api/inventory-counts/${id}/product-batches`;

const createRes = await fetch(url, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    inventoryCountId: id,            // falls dein Backend dies verlangt
    productId: selectedItem.productId,
    warehouseId: inventurData!.warehouseId,
    batchNumber: autoBatchNumber,
    expiryDate: expiryDateString,
    initialQuantity: selectedItem.countedQuantity || 1,
    currentQuantity: selectedItem.countedQuantity || 1,
    notes: `Auto-erstellt bei Inventur #${id}`
  }),
});
if (!createRes.ok) {
  const errText = await createRes.text();
  throw new Error(`Batch konnte nicht angelegt werden: ${createRes.status} – ${errText}`);
}

Prüfe anschließend im Network-Tab deines Browsers, ob der Request jetzt 200 OK zurückliefert und das Antwort-JSON das neue batch.id enthält.

	2.	React-Query-Cache optimistisch updaten statt full refetch
Ersetze dein invalidateQueries(...) in den Mutations-Callbacks durch ein gezieltes queryClient.setQueryData (oder arbeite vollständig mit lokalem State), z. B.:

updateBatchMutation.mutate(
  { itemId: selectedItem.id, batchId: finalBatch.id },
  {
    onMutate: () => {
      // Scroll-Position merken
      const scrollY = window.scrollY;
      return { scrollY };
    },
    onSuccess: () => {
      queryClient.setQueryData(
        [`/api/inventory-counts/${id}/items`],
        (old?: InventoryCountItem[]) => old?.map(item =>
          item.id === selectedItem.id
            ? { ...item, batchId: finalBatch.id, batch: finalBatch }
            : item
        )
      );
    },
    onSettled: (_, __, ___, context) => {
      // Scroll-Position wiederherstellen
      if (context?.scrollY !== undefined) window.scrollTo(0, context.scrollY);
    }
  }
);

Außerdem in deiner useQuery für die Inventur-Items:

useQuery({
  queryKey: ['/api/inventory-counts/${id}/items'],
  refetchOnWindowFocus: false,   // kein ungewolltes Neuladen bei Fokus
  // …  
});


	3.	Sofortige UI-Aktualisierung aus lokalem State (alternativ)
Wenn du lieber komplett ohne Query-Invalidation arbeitest, halte alle InventoryCountItem in einem useState(countedItems), patch diesen State in updateBatchMutation.onSuccess oder direkt in handleBatchUpdate und rendere ausschließlich danach.

⸻

Zusammenfassung des Problems und Lösungswegs
	1.	Problem:
	•	Charge-Anlage: Falscher API-Endpunkt bzw. unvollständiges Payload führt zu HTTP-Fehlern.
	•	Scroll-Reset und UI-Inkonstanz: Vollständiges Refetch invalidiert alles, Seite springt nach oben und zeigt die Charge nie an.
	2.	Lösungsweg:
	•	API-Aufruf reparieren: Verwende den korrekten URL-Pfad (/api/inventory-counts/${id}/product-batches) und sende alle nötigen Felder (z. B. inventoryCountId).
	•	Optimistische Updates statt invalidateQueries: Sorge dafür, dass dein lokaler Cache direkt das neue batch bekommt, und verhindere automatisches Refetch on Focus.
	•	Scroll-Position merken & wiederherstellen (via onMutate/onSettled) oder komplett lokale State-Verwaltung nutzen.

Mit diesen Anpassungen läuft die Batch-Erstellung stabil durch, die neue Charge erscheint sofort unter dem Produkt, und die Seite bleibt da, wo der Nutzer gerade war.
